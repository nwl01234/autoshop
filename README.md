# 🛍 AutoShop Portfolio · [nwl01234.github.io/portfolio-app](https://nwl01234.github.io/portfolio-app/)

**Магазин-портфолио, каждый товар которого — работающий проект.**
Покупатель выбирает решение в каталоге (сайт или Telegram-бот), собирает корзину — и бот сам доводит сделку до оплаты, списывает остаток и записывает продажу. Остатки сайта и бота синхронизированы автоматически: бот коммитит каталог в репозиторий через GitHub API.

> Не «страница со скриншотами», а рабочая система продаж: ⚡ статический фронт на GitHub Pages (0 ₽ инфраструктуры) + автономный Telegram-бот + AI-консультант.

## Архитектура

```
┌────────────────────┐        ?start=ORD<b64>        ┌──────────────────────┐
│  GitHub Pages сайт │ ────────────────────────────► │   Telegram-бот       │
│  index.html + SPA  │   корзина кодируется в ссылку │   aiogram 3 (FSM)    │
└─────────┬──────────┘                               └─────────┬────────────┘
          │  data/products.json (остатки+каталог)              │ оплата ✓
          │  ◄── PUT /contents/ (GitHub API, commit) ──────────┤
          ▼                                        журнал ▼
   Pages пересобирается сам                 data/sales.db (sqlite)
                                            кто · что · когда · канал
```

- **bot/payload.py** — кодек round-trip между сайтом и ботом, покрыт тестами; Telegram accepts только `[A-Za-z0-9_-]`, кодек соблюдает это.
- **bot/storage.py** — единственный источник правды `data/products.json` для сайта и бота; после оплаты бот обновляет файл локально и коммитит в репо.
- **bot/nlu.py** — интенции по паттерну → fuzzy-фолбэку; товар ищется по точному ключу → fuzzy. Понимает «хачу католог», «мини-срм», «ттс колл центр».
- **bot/faq.md** — база знаний оффлайн-консультанта (без GPT-ключей): продающие доводы и работа с возражениями по каждому товару.
- **Отказоустойчивость**: нет `GITHUB_TOKEN` → бот пишет локально; нет `отсутствие AI-ключей → оффлайн-движок на базе знаний. Магазин никогда не «падает лицом».

## Быстрый старт

```bash
git clone https://github.com/nwl01234/portfolio-app
cd portfolio-app

# 1. Виртуальное окружение (обязательный шаг)
python -m venv .venv
.venv\Scripts\activate            # Windows  |  Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt

# 2. Секреты
copy .env.example .env            # вписать BOT_TOKEN и GITHUB_TOKEN

# 3. Бот: polling, никакого публичного URL не нужно
#    при старте бот пишет data/bot_status.json online — сайт сразу показывает «Бот на связи»
#    при остановке (Ctrl+C) — offline, «Бот сейчас офлайн»
python -m bot.run

# 4. Локальный предпросмотр сайта (на GitHub Pages он уже развёрнут)
.venv\Scripts\python.exe -m http.server 8080

# 5. Тесты ядра
.venv\Scripts\python.exe -m pytest tests -q
```

### Деплой сайта (GitHub Pages)
1. Repo → Settings → Pages → Source: `main` / (root).
2. Готово: `https://nwl01234.github.io/portfolio-app/`.

### Права PAT
`GITHUB_TOKEN` — Personal Access Token с правом `contents: write` на репо — только так бот может коммитить остатки.

## Сценарий покупки (проверен тестами)

1. Сайт: `Купить` → корзина в localStorage → `Оплатить через Telegram`.
2. Бот: получил корзину из ссылки → спросил имя → контакт → чек → `✅ Оплатить`.
3. Автоматически: списание остатка → запись продажи (кто/что/когда) → коммит в репо → сайт показывает свежие остатки.

## Приватность TTS-кода

Код **AI Call Center** намеренно не входит в этот публичный репозиторий (см. `.gitignore`): проект продается витриной `/tts.html` + демо через владельца. Для сохранности держится в **приватном** репо — код никогда не утекает в открытый доступ.
